Reading of Part 2
-----------------

The repository is CLEAN: 388 tracked path names, zero findings on every
one of the eight rules, exit 0. That is a negative result and it is
reported as one rather than dressed up.

Two things make that number worth something:

* The relocation proof. The same tracked tree scanned from two
  differently NAMED absolute paths produces byte-identical canonical
  JSON (same SHA-256, cmp agrees), and grepping the report for any of
  /root, /tmp, /home, repoA or repoB prints 0. The report is a function
  of the path names alone, not of where the checkout lives.

* The positive control. Adding a single README.MD beside the existing
  README.md -- a pair that ext4 accepts and macOS/Windows do not --
  flips the same command to exit 1 with exactly one finding,
  CASE_FOLD_COLLISION ["README.MD", "README.md"]. The clean result above
  is a measurement, not a no-op.

What the clean result does NOT establish: nothing here was run on macOS
or Windows. CASE_FOLD_COLLISION uses Python's str.casefold(), which is
not any real filesystem's folding table, and the 260-character MAX_PATH
limit is not checked at all. See "3 limitations a reviewer should
scrutinise" in README.md.
