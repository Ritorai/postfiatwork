crosspath-runner -- relocated-checkout regression evidence
============================================================

What this file is: deterministic evidence that the README exit-code-table
fix (see README.md, "### Exit codes") and its regression tests
(test_exit_codes.py) behave identically from the original checkout and
from a second, differently-named, differently-located copy of the whole
repository. This is exactly the property crosspath-runner itself checks
for other tools, applied here to the change made in this directory.

Environment: CPython 3.11.15, Linux x86_64, stdlib only, no network.

Normalisation disclosed (applied ONLY when comparing, never written back
into any committed file): the `unittest -v` transcripts contain one
genuinely volatile field, the run duration on the "Ran N tests in X.XXXs"
line (e.g. "3.341s" vs "3.045s" above -- real wall-clock variance between
two runs on the same machine, nothing to do with location). For the
byte-comparison below only, that field was replaced with the literal
string <DURATION> via
`sed -E 's/Ran ([0-9]+) tests? in [0-9.]+s/Ran \1 tests in <DURATION>s/'`
in a scratch copy; the files as captured above and the source files in
this repository are untouched. No other field varied and no other
normalisation was applied. transcript-drift/driftcheck.py's own report
needed no normalisation at all -- it is documented to contain no
timestamps or durations by construction (see its module docstring), and
the two runs were confirmed byte-identical without alteration.

What this fix does and does not change
----------------------------------------
Does: makes the exit-code table's header cell match
`transcript-drift/driftcheck.py`'s `TABLE_EXIT_HEADER_RE`
(`^\|\s*\**exit\b`), so all three rows -- `0`, `1`, `2` -- are harvested as
README exit-code claims instead of only `1` and `2` (verified directly:
`readme_exit_claims()` returned `{1, 2}` against the README text before
this change and `{0, 1, 2}` after, with no other change to either file).

Does NOT: change transcript-drift/driftcheck.py's overall verdict for this
directory today. Its ONLY finding for crosspath-runner, unchanged before
and after this fix, is TRANSCRIPT_HAS_NO_COMMAND_RECORDS -- because
captured_output.txt is one of the repository's pre-FORMAT.md prose
transcripts (no `=== $ command ===` headers), and driftcheck's own
`compare()` returns as soon as a transcript has zero records, before it
ever reaches the exit-code comparison. An EXIT_CODE_MISMATCH for the
unacknowledged `0` was never actually produced by a real driftcheck run
against this repository's committed transcript -- confirmed by running
driftcheck before touching anything -- because that earlier-firing check
pre-empts it. The header fix is still correct and worth making now: it
removes a real, verified gap in what the README's own table can convey to
a mechanical reader, and it means the eventual migration of this
directory's transcript to FORMAT.md (out of scope here; a separate task
covers all seven pre-FORMAT.md transcripts in this repository) will not
also need a documentation fix at that time -- the table will already be
correct and machine-readable.

Also does NOT: change the repository-wide driftcheck exit code (`1` in
both checkouts, before and after) -- there are unrelated findings in other
tool directories (see drift_counts above) that this patch does not touch
and does not claim to fix.
