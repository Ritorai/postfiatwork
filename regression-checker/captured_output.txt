Reading of Part 2
-----------------

Defect 1: pre-fix, `"expected_exit_code": false` loads without complaint
and okzero -- which exits 0 -- is reported `"status": "clean"`, because
`0 == False` is True in Python. Post-fix it is a setup error (exit 2)
naming the entry and the reason.

Defect 2: pre-fix, a process killed by SIGKILL that left a truncated
30-byte report on disk is reported `"status": "clean"`, `"drift_codes":
[]`, because -9 was compared as if it were an exit status and the partial
bytes hashed as if they were a finished report. Post-fix the same run
carries `"termination": "signalled"`, `"signal": 9` and the
ABNORMAL_TERMINATION drift code, and --update-baselines refuses to write
that run into the baseline at all.

Note in both pre-fix runs that the *other* tool in the directory is
correctly reported UNBASELINED_TOOL. The pre-fix checker was working as
designed; the designs of these two checks were wrong.
